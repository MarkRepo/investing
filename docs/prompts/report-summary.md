# 研报摘要提示词

适用于：券商研报、咨询机构报告、行业白皮书等独立完整的分析作品。

> **目标**：读者看完此页，无需读原研报，也能精准、完整、无错漏地 get 全篇核心论点、关键数据和论证逻辑。

结构、章节名、内容取舍完全自由，服从研报的内在叙事逻辑，不套通用模板。
摘要内容要符合以下几个维度的要求：

| #   | 维度   | 检验标准                                           |
| --- | ------ | -------------------------------------------------- |
| 准  | 事实准确 | 无数据/公司名/政策/论据错误，不曲解分析师原意，不张冠李戴，不主观脑补 |
| 核  | 抓住核心 | 紧扣研报的核心投资逻辑/产业论点，主线论证链条完整，不跑偏次要信息 |
| 精  | 极简浓缩 | 不照搬原文，但关键数据（市场规模、CAGR、份额、测算值）必须保留；去掉所有铺垫话和过渡句 |
| 逻  | 脉络清晰 | 还原研报的论证结构——为什么是这个行业、为什么是现在、怎么论证、结论是什么——各部分因果关系清楚 |
| 专  | 内容专属 | 不套通用模板，不是所有研报都能替换名字复用的空话，内容锁定这篇研报的独有逻辑和数据 |
| 全  | 无遗漏   | 核心论点、关键数据、测算逻辑、推荐标的/战略建议、风险提示无遗漏；次要行业背景可省，主干不丢 |

补充硬约束：

1. **量化保留**：原文明确给出的数字（百分比、金额、时间、温度、吨数、公里数、PE 倍数、产能、订单金额）必须原样保留；确需近似（如 49.996 亿 → 约 50 亿）必须在文末"精度损失"部分列出。
2. **反幻觉**：摘要只能复述或浓缩原文，不得补充原文未给出的推演、判断、类比或时间预测；若必须做跨段落推断，需以"由此可推"/"我们理解为"等标记，且不得出现在风险提示等严肃断言位置。
3. **笔误修正**：若发现原文单位/数字明显排版错误（如 m² 应为 m³），可在摘要中采用修正值，但必须在文末"原文修正"部分列出（原文 X → 修正为 Y，依据：...）。

---

## 输出格式

输出 **带 YAML frontmatter 的 Markdown 文件**，写入 `mineru_summaries/{report_id}.md`：

```
---
report_id: {report_id}
title: {标题}
topic: {行业/主题}
source_pdf: {原始 PDF 文件名}
source_dir: {MinerU 输出目录名}
model: {调用此 prompt 的模型 ID，如 sonnet46 / gemini-3.1-pro / qwen36plus}
generated_at: {ISO 8601 时间戳}
---

{摘要正文}
```

同时在 `mineru_summaries/registry.json` 中追加或更新对应条目，字段与 frontmatter 一致（去掉正文）。
