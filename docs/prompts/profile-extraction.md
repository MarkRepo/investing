# profile-YYYY.md 抽取 Prompt（年报 → 事实层草稿）

从年报 / 10-K / 20-F 抽取**当年的公司事实层快照**，输出 `profile-YYYY.md` **草稿**。
这一层权威性高于 claims，需要你**人工审阅改定**后再落盘，**不进任何自动入库管道**。

---

## 和 claims 抽取的区别

| 维度 | claims（§3.6） | profile-YYYY |
|---|---|---|
| 来源 | 研报、纪要、新闻 | 仅年报/10-K/20-F/公告 |
| 主观性 | 作者观点 | 客观事实 |
| 时间 | 跨时段累积 | 按年版本化（每年一份） |
| 入库 | 批量校验后自动入 `claims.jsonl` | **人工改定后手动保存** |
| 数量 | 每篇 8-40 条 | 每年一份，结构化 markdown |
| 更新触发 | 每次新研报 | 年报发布 |

> **DESIGN §坑 9**：事实层只接受年报/公告/多份研报交叉验证，不接受新闻。`profile.md` 一旦污染，整个系统的信号会失真。

---

## 流程

1. 把年报全文（或关键章节：业务描述、MD&A、合并财务、附注、风险因素）贴进 Claude 对话
2. 附上本 prompt 作为系统指令
3. Claude 返回 markdown 草稿
4. 你**逐段审阅**，特别是数字和业务描述，改错/补漏
5. 保存到 `companies/{market}_{ticker}/profile-{year}.md`
6. 如果年报里信息不足，**留空不要编**，在该字段下写 `_未披露_`

## 审阅 checklist（你改定时逐项过）

- [ ] 数字和年报原件对账（特别是收入、毛利、有息负债）
- [ ] 货币单位、精度（百万 vs 亿）没错
- [ ] 业务本质一句话能让外行明白
- [ ] 收入/地域分部和年报分部披露口径一致
- [ ] 关联方 / 集中度 / 审计意见（这三项是红旗雷达）
- [ ] 风险因素是**年报原话**，不是 Claude 自己的总结
- [ ] `reviewed: true` 在 frontmatter 里切换

---

## 反例

- ❌ Claude 根据新闻/研报补齐年报没披露的客户集中度 → 污染事实层
- ❌ "收入 28.7 亿" 但年报披露单位是百万美元（应为 $2.87B 或 287 百万）
- ❌ "风险因素：增长不及预期" 这种空洞复述 → 必须引用年报具体风险条目
- ❌ 把 MD&A 里的前瞻性陈述写进"业务本质" → 那是管理层展望，不是事实层
