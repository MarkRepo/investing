# surf · 趋势跟随系统 设计

> 状态：设计已确认，待实现
> 日期：2026-09-21
> 与 prism 的关系：**无逻辑关系**。独立目录、独立数据、独立工作流，仅共用 FastAPI 服务与模板层以便统一查阅。

## 1. 它解决什么

业余选手难以发现趋势，只能跟随趋势。本系统的目标是：**在当下找出正在发生的产业趋势，用市场资金行为交叉验证，给出可跟随的交易对象和完整理由**，吃到主升浪，或第一波大回撤后的二波反弹。

与 prism 的根本区别：prism 是价值投资研究（企业内在价值）；surf 是趋势跟随（资金、人气、产业趋势驱动），**不基于价值投资**。

## 2. 核心设计：2×2 判定矩阵

整个系统的判断逻辑就是这张表：

|  | 技术确认（资金在押注） | 技术未确认 |
|---|---|---|
| **产业逻辑成立** | ✅ **可跟随** —— 唯一出手的格子 | ⏳ **太早 / 埋伏区**：逻辑对但市场未认，观察不动手 |
| **产业逻辑不成立** | ⚠️ **纯炒作** —— 明确排除，入黑名单 | ⬜ 忽略 |

「纯炒作」的判定标准不是统计意义上的「涨完就崩」，而是 **「找不到真实产业变化来解释这次上涨」**。这个判定只需要当下的产业调研，不需要历史数据。

## 3. 关键决策：不做历史回测

**决定**：本系统不做历史回测，不基于历史统计验证规则。趋势判断基于当下的产业分析 + 当下的市场技术佐证。

**理由**：
- 用户明确要求基于当下判断，历史对其决策无意义。
- A 股板块指数历史数据存在严重前视偏差（见附录 A 的实证），回测结论不可信。
- 回测在统计上难以区分真趋势与炒作（两者价格形态高度相似），而定性分析恰好擅长此事。

**代价（明确承认，不粉饰）**：
- 没有胜率、盈亏比、期望值等任何客观有效性证据。
- 唯一的验证方式是向前验证：记录每次判断，事后回看。
- 系统质量的唯一变量是产业分析的质量。

**澄清**：技术佐证层仍然读取近 250 个交易日的价格数据，用于计算相对强度和判断板块位置。这是「用历史数据判断当下状态」，不是「用历史统计验证规则」，两者性质不同。

## 4. 双通道工作流

主通道是产业在先，技术为佐证。

### 通道 A（主）· 产业趋势发现 → 技术佐证

**频率**：每周一次全局扫描。重大事件随时加扫。

1. 扫描当下真实发生的产业变化：政策落地、技术拐点、供需反转、产品价格异动、产能周期、大厂资本开支、订单与排产、渠道反馈。
2. **这一步刻意不看行情**，避免被价格牵引导致事后合理化。
3. 产业结论先落笔并带时间戳，再去市场查证：资金认不认、板块位置在哪。

### 通道 B（辅）· 技术异动扫描 → 反查产业逻辑

1. 脚本扫描 A 股与美股全部候选 ETF，找出正在异动的标的。
2. 对异动标的反查产业逻辑。
3. 两个作用：兜住通道 A 漏掉的趋势；**找不到产业逻辑的异动即判定为纯炒作，入黑名单**。

两条通道必须都有。只有 B 会让系统退化为「涨了就找理由」的事后合理化机器 —— 这是不做回测这条路上最大的陷阱。

## 5. 防自我欺骗机制

不做历史验证，最大风险是分析者编造理由说服自己。两条硬机制：

1. **证伪条件强制**：每张趋势卡片必须写明「什么情况下我认为自己错了」，且必须是可观测的具体事实（例：某产品价格跌破 X、某公司月度出货低于 Y、标的失守 Z 价位）。**没有证伪条件的卡片不允许发出。**
2. **产业判断先于价格判断落笔**：通道 A 的产业结论在查看行情之前写入文件并带时间戳。事后如有改口，保留改动痕迹（git）。

## 6. 技术佐证层

### 6.1 扫描对象：统一扫 ETF

两个市场方法论统一，扫描对象直接就是可交易标的，无映射损耗。

| 市场 | 对象 | 数据源 | 说明 |
|---|---|---|---|
| A 股 | 行业/主题 ETF（约 150-250 只） | 新浪 `fund_etf_category_sina` + `fund_etf_hist_sina` | ETF 净值由实际交易产生，无回溯合成问题 |
| 美股 | 行业/主题 ETF（约 40 只） | yfinance | 行业 SPDR 11 只 + 主题 ETF（SMH/XBI/ITA/TAN/IGV/URA/KWEB/HACK/LIT/XME/JETS/IYT/XHB 等） |
| A 股辅助 | 同花顺 90 行业 + 375 概念的资金流与涨跌家数 | `stock_fund_flow_industry` / `stock_fund_flow_concept` / `stock_board_industry_summary_ths` | 仅作资金面与热点佐证，**不做趋势判断** |

**A 股 ETF 筛选标准**：排除货币、债券、宽基（沪深300/中证500/上证50等）、商品 ETF；规模 > 5 亿；近 20 日日均成交额 > 3000 万；同一主题保留规模最大的一只。

**已知限制**：同花顺 375 个概念板块无历史指数接口，因此概念层只能使用当日截面数据（资金流、涨跌幅、涨跌家数），无法判断位置与趋势。概念主题的趋势判断依赖是否存在对应 ETF。

### 6.2 计算指标

对每个 ETF 计算：

| 指标 | 定义 | 用途 |
|---|---|---|
| 相对强度 RS | 20 日 / 60 日涨幅在全部候选中的百分位排名 | 谁在跑赢 |
| 位置 | 现价在近 250 日高低区间中的分位（0-100%） | 山脚还是山顶，防追高 |
| 趋势结构 | 价格 vs 20/60 日均线，20 日线 vs 60 日线 | 是否处于上升结构 |
| 量能 | 近 5 日成交额 / 前 60 日日均 | 是否放量 |
| 距高点回撤 | 现价距近 250 日最高点的回撤幅度 | 识别「二波」形态的前提 |
| 资金流（仅 A 股） | 同花顺对应板块近 5 日资金净流入 | 资金态度 |
| 广度（仅 A 股） | 对应板块当日上涨家数 / 总家数 | 防少数权重股伪装成板块行情 |

指标只用于**描述当下状态**，供产业分析交叉参考，**不构成自动买卖信号**。出手与否由 2×2 矩阵判定。

### 6.3 ETF 与板块的映射

资金流与广度是板块层指标，而扫描对象是 ETF，两者需要映射。

- 维护一张人工映射表 `surf/etf_board_map.yaml`，形如 `512480(半导体ETF) → 同花顺"半导体"`。
- **不强求全覆盖**：仅对有明确对应板块的 ETF 建立映射；无映射的 ETF 照常计算价格类指标，资金流与广度字段留空。
- 映射表随使用逐步补充，不在第一期追求完整。

美股无对应的板块资金流数据源，全部 ETF 的资金流与广度字段留空。这是两个市场的既有差异，不强行对齐。

## 7. 产出物：趋势卡片

系统的唯一产出物。每张卡片回答用户提出的全部问题。

```
趋势名称
─────────────────────────────
① 趋势成因与背景
   驱动力类型（政策 / 技术 / 供需 / 业绩 / 事件）
   证据链：订单、产能、价格、资本开支等可核实事实
② 阶段判断
   0→1 导入期 / 1→10 放量期 / 10→100 成熟期
③ 技术佐证
   相对强度排名、位置分位、趋势结构、量能、资金流、广度
④ 上涨空间
   测算方法（渗透率 × 市场规模，或类比同类趋势幅度）
⑤ 交易对象
   ETF（打底）+ 龙头个股 2-3 只
   选择理由：卡位 / 弹性 / 业绩兑现度 / 筹码结构
⑥ 交易计划
   入场条件、硬止损 8-10%、目标位、仓位建议
⑦ 证伪条件
   什么情况下承认判断错误（必填，可观测）
```

## 8. 交易系统

```
只在 2×2 矩阵左上角出手
    ↓
板块 ETF 打底 + 龙头个股增强
    ↓
硬止损 8-10%，不留情面
    ↓
持有 3 周 - 3 个月
    ↓
证伪条件触发 or 产业逻辑破坏 → 无条件离场
```

**优势**
- 理由完整可读，非黑箱，用户可自行判断是否认同。
- 能排除纯炒作（这是回测做不到的）。
- 止损规则简单，无需临场判断。
- 信号少，适合业余选手的精力投入。

**劣势**
- 无胜率数据，有效性无客观证据。
- 信号频率低（真实产业趋势一年仅数个）。
- 定性判断可能出错，且错了未必知道为什么错。
- 产业分析质量是唯一变量，无法工程化保证。
- 跟随策略的固有代价：确认趋势时往往已上涨一段，靠硬止损控制。

## 9. 目录与存储

文件驱动，第一期不引入数据库。

```
surf/
├── DESIGN.md              本设计的权威版（实现后从本 spec 迁入）
├── scans/
│   └── YYYY-MM-DD/
│       ├── cn_etf.csv         A股 ETF 指标快照
│       ├── us_etf.csv         美股 ETF 指标快照
│       ├── cn_boards.csv      同花顺板块资金流快照
│       └── summary.md         本次扫描摘要
├── cards/
│   └── {slug}/
│       ├── card.md            趋势卡片
│       └── log.md             决策日志（向前验证用）
├── blacklist.yaml         判定为纯炒作的板块/主题，附判定日期与理由
├── etf_board_map.yaml     ETF → 同花顺板块映射（人工维护，允许不全）
└── scripts/
    ├── scan_cn.py         A股 ETF + 板块资金流扫描
    ├── scan_us.py         美股 ETF 扫描
    └── etf_universe.py    ETF 候选池筛选与维护
```

**脚本零 LLM 调用**（沿用 prism 的分工哲学）：脚本只做数据抓取、指标计算、文件读写；所有产业判断与趋势推断由 Claude 在对话中完成。

## 12. 附录 A：A 股板块指数历史数据的前视偏差（实证记录）

设计过程中对同花顺板块指数做了数据质量检验，结果如下（2026-09-21 实测）：

```
同花顺行业指数
  电池        2010-01-04 起，基期 996.7  → 累计 +1657%
  光伏设备     2010-01-04 起，基期 998.3  → 累计  +606%
  能源金属     2010-01-04 起，基期 1000.5 → 累计 +2819%
  电子化学品   2010-02-12 起，基期 1043.9 → 累计 +8749%
  美容护理     2010-01-04 起，基期 991.8  → 累计  +381%
  银行(对照)   2010-01-04 起，基期 1103.3 → 累计   +24%

申万行业指数（对照）
  美容护理(2021新设)  2021-12-13 起，首值 8179.5   ← 只从真实发布日开始
  环保(2014发布)      2014-02-21 起，首值  997.5
  电力设备(2021改名)   2014-02-21 起，首值 3836.7   ← 延续原指数真实点位
  电子(1999发布)      1999-12-30 起，首值 1000.0
```

**结论**：电池、光伏设备、能源金属、电子化学品、美容护理均为 2021 年新设分类，同花顺却给出了始于 2010 年、基期恰为 1000 点的历史序列，且收益率呈现幸存者偏差的典型特征（电子化学品 87 倍）。这些历史由当前成分股名单倒推生成，在现实中从未发生。申万对同一分类只提供真实发布日之后的数据，是干净的。

**这是本系统放弃历史回测的技术原因之一**。若未来需要历史验证，数据源必须使用申万行业指数或 ETF 实际净值，不得使用同花顺板块指数。

## 13. 附录 B：与 prism 的隔离边界

| 项 | prism | surf |
|---|---|---|
| 方法论 | 价值投资，企业内在价值 | 趋势跟随，资金/人气/产业趋势 |
| 目录 | `prism/` | `surf/` |
| 数据 | `prism/topics/`、`data/financials.db` | `surf/scans/`、`surf/cards/` |
| 工作流 | `prism/workflows/` | `surf/`（第一期在对话中进行，不建 workflow 文件） |
| web | `/prism` | `/surf`（第二期） |
| 共用 | FastAPI 服务（`main.py`）、模板层、`app/io/adapters` 数据适配器 | 同左 |

代码零交叉：surf 不 import prism 任何模块，prism 也不感知 surf 的存在。共用仅限于基础设施层。
