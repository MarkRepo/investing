## 0. 一句话目标

把第一期那个**静态、一次性快照**的宏观层，升级成一个**输入完整、机制可核验、按节奏动态拉取、由用户在 web 端被提醒后主动重判**的活框架。

---

## 1. 背景与动机

第一期建好了宏观三体制（利率/流动性/汇率）的骨架与一次性读数，但有三处硬伤，是本期要补的：

1. **输入是死的**：regime_read v1 的指标是手动快照一次。会影响判断的输入（指标 + 描述性政策）应当**按各自频率动态拉取**，结论才能及时更新。
2. **驱动层缺失 + 无机制图**：第一期把"增长/通胀/政策/财政"列了名却没结构化捕获；更关键的是，**没有任何地方写下"某输入凭什么影响目标、通过什么机制、是因果还是相关、滞后多久"**——框架因此不可审计、不可证伪。
3. **判断与抓取没解耦**：没有"抓取自动跑 / 判断人触发"的分工，也没有 web 端提醒回路。

### 1.1 用户的核心诉求（驱动本设计）

- 所有**会影响三目标判断**的输入都应动态获取——不仅是结构化指标，也包括**描述性政策**（FOMC 声明、货币政策执行报告、央行讲话）。
- 抓取/资料按**固定频率自动拉取**；**判断/重判由用户在 web 端被提醒后主动执行**。
- **输入不能有遗漏，且每个输入都要有监控**。
- 用**因果机制**而非用户的临时提示来决定"该不该抓"；并严格**区分因果关系与相关关系**（例：利率→黄金是因果；黄金↔比特币是相关，二者都被利率驱动）。
- 元诉求（决定了本设计的方法论）：用户是宏观门外汉，无法审计架构师。框架的可信度**不能靠"相信我"**，必须架到用户可独立核验的外部轨道上。

### 1.2 校准工序（本设计的证据来源）

为回应 1.1 的元诉求，落 spec 前跑了一轮 11-agent 并行校准（**不依赖用户提示生成缺口**）：

- **4 路外部标准对标**（web 取真源）：美联储反应函数（FOMC/SEP/FSR）、金融条件指数（NFCI/GS/Bloomberg/FCI-G）、BIS/IMF 全球流动性与美元融资、中国货币信用汇率框架（PBoC/SAFE）。
- **4 路独立冷推导**（不喂现清单、混用 Opus/Sonnet 去相关）：资产定价/反应函数、交易台实战、跨资产资金流、中国与中美联动。
- **3 路红队**：找缺失输入、挑因果/相关机制错误、框架失效场景与盲区。

校准结论（详见 §3–§6）：① 补出大量来自独立来源的缺口；② 推翻了若干原机制判断（含本对话中我此前的添加）；③ 暴露出"行情型只显示不报警"的突变盲区与一批结构性成熟度缺口。**本设计据此（而非据用户提示）定型。**

## 2. 输入分层与机制模型（成熟化的核心）

不再是"一堆指标"，而是**每个输入都申报一条机制边**。

### 2.1 三层准入规则（"是否影响目标"的判定法）

| 层 | 准入条件 | 待遇 |
|----|---------|------|
| **A 逻辑链** | 能写出站得住的**因果句** `X → 经 Y → 目标(利率/流动性/汇率)↑/↓` | 进 regime read，参与判断 |
| **B 交叉印证** | 只是**同步度量**同一体制（相关、非因果），用于印证，**明确不当成驱动** | 常驻显示 + 合成时作旁证 |
| **C 仅展示/备用** | 无已确立机制，先接入展示、为后续/资金流观察备料 | 只显示；证出因果通道可升 A |

### 2.2 每个输入的机制字段（登记表 schema）

| 字段 | 取值 |
|------|------|
| `name` | 输入名 |
| `tier` | A / B / C |
| `cadence_type` | **事**=事件型(按发布) / **行**=行情型(连续) / **述**=描述型(政策文本) |
| `targets` | rates / liquidity / fx 的子集（可多个） |
| `mechanism` | **CD**=因果驱动 / **CF**=资金流渠道(因果子类) / **CO**=同步读数 / **CR**=仅相关 |
| `causal_sentence` | 一句话因果链（CD/CF 必填） |
| `lag` | 领先/同步/滞后 + 大致时长 |
| `importance` | 承重 / 确认 / 背景（决定抓取力度，见 §4） |
| `source` | FRED / web / 央行 / 统计局 / SAFE / 财政部 / HKEX / TBD |
| `fetch_method` | fred-api（零LLM自动） / llm-web / manual / TBD |
| `state` | 已有(v1已结构化) / 新增 / 改(重新分层或升级) |
| `alert_series` | 布尔：是否属"突变报警序列"（见 §4.3） |

**因果/相关纪律**：`tier A` 必须 `mechanism ∈ {CD, CF}`；`CO/CR` 只能 B 或 C。`CF`（资金流渠道）是因果子类——机制是"钱在资产/地区间搬家"，所以日元 carry 平仓可入 A，而比特币与股票齐涨（共同被流动性驱动）只能 C。

## 4. 动态监控设计（抓取自动 / 判断人触发）

复用 prism 现有 monitor 机器（`06-daily-monitor.md` + `monitor.py` + `monitor_queue.yaml` + manifest 的 `stale_at/expire_at`），把宏观 topic 接进去。

### 4.1 频率

**一天一次扫一次**即足够（宏观多为月度/事件；只有收益率/利差/汇率/OAS 是日动）。日扫**不等于**每天重搜 80 个：事件型按发布日历到点附近才抓；行情型走 FRED 等便宜接口近乎零成本。

### 4.2 三类输入的处理

- **事件型(事)**：有新发布 = 真有新信息 → **diff 即提醒**，web 展示新旧对比。
- **描述型(述)**：按发布日历（FOMC 8次/年、MPR 季度、政治局会议等）到点抓全文 → 抽 findings → **有实质变化即提醒**。走 prism 现有资料(manifest)管线。
- **行情型(行)**：**采用"甲+阈值升级"混合**（见 4.3）。

### 4.3 行情型：甲 → 混合（校准工序逼出的关键修正）

纯"甲（只显示不报警）"会把**体制突变最先出现的连续序列静音**（Aug2024 日元carry崩、2020 COVID 基差爆裂、2022 gilt/LDI——全无日历事件）。故修正为：

- 小动：仍**只常驻显示最新值 + 较上次变化**，不打扰（守住"别天天烦我"）。
- **对一小撮 regime-critical 行情序列做 z-score/速度自动升级报警**：
  **MOVE / HY OAS / 跨币种基差 / USDJPY-日元carry / CNH-CNY 价差 / DR007**（`alert_series=true`）。
- 触发条件：n 日 delta 或 z-score 越过预设带（一个**粗档**，非逐指标精调）。

### 4.4 回路

monitor 认识宏观 topic → 到期/突变 → 写 proposal 进 queue（`awaiting_confirm`，**绝不自动改结论**）→ web 端提醒"宏观输入有更新 N 项 / 体制读数已过期 / 承重序列 X 越带，建议重判"→ 用户看 diff → 说「合成 global-macro」走 `_macro_regime.md` 重出三件套。

## 6. 结构性成熟化升级（输入之外的框架缺口）

校准独立发现的结构缺口，作为本期设计要求纳入 regime_read 与 dashboard：

1. **多维体制读数**：不再"单一综合判断 + 1 个强度分"。三体制各自给读数与**分维度信心**；另设**增长/通胀象限**(复苏/过热/滞胀/衰退)独立于三体制。
2. **fragility 罚分**：强度分与突变风险反相关（越"干净"越临近崩）。综合信心需被脆弱度（利差极窄 + 低波动 + carry 拥挤 + 承重假设数）**折减**，输出"信心6 / 脆弱度高"。
3. **突变探测**（= §4.3 报警序列）：闭合"识别器 ≠ 突变探测器"的最大盲区。
4. **carry 渠道探头**：framework 命名了 carry-久期渠道却无传感器 → 加持仓拥挤/定位输入（§3.3）。
5. **跨目标反馈环**：建"危险组合"查找表（如 利率↑+DXY↑ → 中国流动性被动收紧 的 doom-loop），不再三体制独立串联。
6. **"传导是否还活着"闸**（中国资产负债表衰退）：信贷脉冲符号 + M1-M2 负值持续时长 + 居民信贷增速；持续死则**降货币输入权重、升财政输入**，并下调持仓"宽货币转宽信用"标签。
7. **承重政策假设清单 + 证伪条件**：如"PBoC 保汇率""Fed 通胀优先"列为一等监控对象，任一变化强制重判 + 信心重置。
8. **决策/结果台账**（可证伪战绩）：每期读数 + 机制断言落盘，事后自评分；老错的机制边降级。成熟度靠时间与命中率长出。
9. **max-staleness 看门狗 + regime-decay 指示**：human-trigger 加硬底——读数 N 天未更新且报警序列已动 >z → 强制 flag；dashboard 区分"无新事件"与"读数仍新鲜"（**沉默 ≠ 确认**）。
10. **diff 对轨迹不对单点**：事件型与"上一窗口/趋势"比（连续三个软 NFP 也算信号）。

## 10. 成功标准

- 宏观 topic 有一张**无遗漏、带机制、可审计**的输入登记表，每行都有监控归属。
- 输入按节奏动态拉取；事件/描述型有变即提醒，行情型按 §4.3 混合报警；判断永远由用户在 web 端触发。
- regime_read 是**多维 + 带 fragility + 带新鲜度**的活读数，不再是单分快照。
- 框架的输入完整性与机制正确性**可对照外部标准核验**，且有战绩台账可长期证伪。
- 与 prism 现有 topic/dashboard/monitor 机器同构，web 自动反映。
