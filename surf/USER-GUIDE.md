# surf · 趋势跟随系统 使用说明

> **这份文件回答两个问题：它怎么想的（工作原理）、结果在哪看（输出与判定）。**
>
> | 想知道 | 看哪里 |
> |---|---|
> | 方法论、判定标准、数据陷阱 | `surf/DESIGN.md`（**权威版**） |
> | 怎么执行一次扫描（给 Claude 的操作流程） | `.claude/skills/surf/SKILL.md` |
> | 系统怎么想、我怎么读结果 | **本文件** |
> | 只是想看结果 | 直接跳 [第 3 节](#3-怎么看输出) |
>
> 与 prism **无逻辑关系**：独立目录、独立数据、独立工作流，只共用服务和页面外壳。

---

## 1. 它是什么

**目标**：在当下找出正在发生的产业趋势，用市场资金行为交叉验证，给出可跟随的交易对象、完整理由和证伪条件。吃主升浪，或第一波大回撤后的二波反弹。

持有周期 3 周 – 3 个月（中期波段），A 股 + 美股并重，板块 ETF 打底 + 龙头个股增强。

与 prism 的根本区别：prism 研究企业内在价值，surf **不基于价值投资**，它跟随资金与产业趋势。

**不做什么**（明确的边界，不是待办）：

| 不做 | 为什么 |
|---|---|
| 历史回测 / 统计验证 | 没有胜率、盈亏比、期望值等**任何客观有效性证据**。A 股板块指数历史数据有严重前视偏差（DESIGN 附录 A 实证），回测结论不可信；且回测在统计上分不清真趋势与炒作，定性分析恰好擅长此事 |
| 自动交易 / 持仓管理 | 系统只产出判断，不碰钱 |
| 基本面深研 | 该转 prism。卡在「这家公司能不能兑现」时，卡片会写进 `prism_refs` |
| 盘中价格 | 周频系统，日内价格无决策意义，只认收盘价 |
| 业绩兑现度 / 筹码结构 | 前者属基本面（转 prism），后者无干净数据源 |

**代价明确承认，不粉饰**：唯一验证方式是**向前验证**——每次判断都留痕，事后回看（`cards/{slug}/log.md`）。系统质量的唯一变量是产业分析的质量，无法工程化保证。

## 2. 工作原理

### 2.1 一个判断，四个格子

整个系统的判断逻辑就是这张表（DESIGN §2）：

|  | 技术确认（资金在押注） | 技术未确认 |
|---|---|---|
| **产业逻辑成立** | ✅ **可跟随** —— 唯一出手的格子 | ⏳ **太早 / 埋伏区**：逻辑对但市场未认，观察不动手 |
| **产业逻辑不成立** | ⚠️ **纯炒作** —— 明确排除，入黑名单 | ⬜ 忽略 |

「纯炒作」的判定标准不是「涨完就崩」，而是 **「找不到真实产业变化来解释这次上涨」**。这个判断只需要当下的产业调研，不需要历史数据。

**还有一种情况不在矩阵里，但必须识别：阶段错。** 产业逻辑成立、技术也确认，但主升浪已经走完（扫描 #001 的存储超级周期：MU +518%、SNDK +1641%）。这不算判断错，是入场晚了——所以每个格子里的条目可能带一个「阶段错」标记。

### 2.2 两条通道，缺一不可

```
通道 A（主）  产业扫描 ——→ 技术佐证 ——→ 2×2 判定
              先落笔、带时间戳，写完才允许看行情

通道 B（辅）  技术异动扫描 ——→ 反查产业逻辑
              找得到真实产业变化 → 进入 2×2，可能是 A 漏掉的趋势
              找不到            → 判定纯炒作，写入黑名单
```

**为什么必须两条都有**：只有 B 会让系统退化成「涨了就找理由」的事后合理化机器——这是不做回测这条路上最大的陷阱。扫描 #001 的实证：通道 A 完整漏掉了当时美股最强的主线（云软件 WCLD），由通道 B 补回；而通道 B 单独看会把一根 CEO 表态驱动的脉冲当成趋势，由通道 A 的产业核查扣掉。**两条通道各自纠正了对方一次。**

### 2.3 防自我欺骗：靠顺序，不靠自觉

不做历史验证，最大风险是分析者编造理由说服自己。三条硬机制：

| 机制 | 内容 |
|---|---|
| **落盘先于看价** | 产业结论（`channel_A_industry_scan.md`）和个股候选（`stock_candidates.md`）必须在**查看任何行情之前**写入文件并带时间戳。顺序颠倒 → 退化为「涨了就找理由」/「涨得好的就是龙头」。git 时间戳是证据 |
| **证伪条件强制** | 每张卡片必须写明「什么情况下我认为自己错了」，且必须是**可观测的具体事实**。没有证伪条件的卡片不允许发出 |
| **决策日志只追加** | `log.md` 不修改历史记录。向前验证是本系统唯一的有效性证据来源 |

**第 1 条靠记忆执行必然失效**——新会话没有上下文时，最自然的动作就是先跑脚本看涨跌。这是 `SKILL.md` 存在的首要理由，也是它把「Step 1 完成落盘之前禁止查看行情」写成铁律的原因。

### 2.4 系统有哪几步（Step 0–5）

| 步骤         | 做什么                                               | 产出                                                                   |
| ---------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| **Step 0** | 复查已有卡片的⑦证伪条件，逐条核对。触发即离场                           | 更新 `card.md` frontmatter + 追加 `log.md`                               |
| **Step 1** | 通道 A：产业扫描（政策/技术拐点/供需反转/产能周期/资本开支/订单…）。**全程不看行情**  | `scans/{date}/channel_A_industry_scan.md`                            |
| **Step 2** | 技术佐证：抓全量 ETF → 我判主题 → 出池 → 逐项看指标                  | `cn_etf.csv` / `us_etf.csv` / `themes.json` / 板块三表                   |
| **Step 3** | 通道 B：看 RS 榜首里 Step 1 没覆盖的方向，反查产业逻辑。查不到 → 黑名单      | `blacklist.yaml` 追加                                                  |
| **Step 4** | 填 2×2，产出/更新卡片                                     | `summary.md` + `matrix.yaml` + `cards/{slug}/card.md`                |
| **Step 5** | 个股增强层（只对左上角卡片）：先落盘候选 → 技术验证 → 注册 companies → 写回卡片 | `stock_candidates.md` / `stock_{slug}.csv` / frontmatter 的 `stocks:` |

**Step 0 永远排在最前**：旧仓位的风险优先于新机会。没有这一步，系统只会不断新增卡片而从不淘汰。

### 2.5 脚本与分工

**脚本零 LLM 调用**——只做数据抓取、指标计算、文件读写，可离线重跑、结果可复现。所有产业判断与趋势推断由 Claude 在对话中完成。

- 一律用 `.venv/bin/python`，系统 `python3` 会**静默失败**。
- `scan_cn.py` 需**清代理**（akshare 走国内源），`scan_us.py` 反而**需要代理**（yfinance 走 Yahoo）。
- 指标只用于**描述当下状态**，供产业分析交叉参考，**不构成自动买卖信号**。出手与否由 2×2 判定。

## 3. 怎么看输出

### 3.1 页面入口（四个）

服务由 launchd 托管，页面**只读** `surf/` 下的文件，不写任何东西。

| 页面 | 看什么 |
|---|---|
| <http://127.0.0.1:8000/surf> | **首页**：在跟的趋势卡片 + 本期 2×2 + 扫描历史 + 黑名单 |
| <http://127.0.0.1:8000/surf/card/{slug}> | **单张卡片**：交易参数、证伪条件清单、个股增强层、指标时间序列、正文、决策日志 |
| <http://127.0.0.1:8000/surf/universe> | **候选池漏斗**：扫了哪些、判了什么、盲区在哪 |
| <http://127.0.0.1:8000/surf/scan/{date}> | **某期扫描全貌**：摘要与 2×2、通道 A 原文、五张指标表 |

顶栏导航里叫「趋势」和「候选池」。**只想快速看结果，顺序是：首页看还有没有在跟的 → 卡片页看证伪条件有没有触发 → 候选池看盲区。**

### 3.2 首页 `/surf` —— 我现在该干什么

**① 在跟的趋势**（页面顶部，最先看）

每张卡片一块面板，从左到右读：

- **状态徽章**：`可跟随` / `可跟随 · 低优先`（仓位权重更低）/ `已离场`
- **`阶段` 与市场徽章**：如 `1→10 放量期 · 早中段`、`CN/HK`
- **进度条**：左端止损、右端目标，指针是现价。位置越靠右越接近目标，越靠左离止损越近
- **`距 ma60` / `距 硬止损`**：**两道止损里先触发的那道**会被标出来——不标明会被误读成硬止损。数字超过 ~10% 会标红
- **`距目标` / `盈亏比`**
- **`证伪条件 x/y 触发`**：这是每周要核对的。**大于 0 就标红**
- **`个股 n 只 · 观察 m`**：ETF 触发证伪则个股无条件同步离场
- **`量能比`**：`< 1`（未放量）会标黄加 `⚠未放量`
- **`广度` / `板块资金` / `ret60`**：港股 ETF 与跨板块主题不做板块映射（DESIGN §6.3），字段显示 `—` 是设计如此，不是缺数据

> ⚠️ **这一块里有两个日期的数据源，页头分别标了出来**：`现价` 与进度条取 `latest_quotes.csv` 的**最新收盘价**，右侧的 `量能比` / `广度` / `板块资金` / `ret60` 来自**当期扫描快照**。两个日期相同时会显示同一个日期，但含义不同——**要判断价格与建卡参数是否还对得上，看卡片页的漂移警告框（3.3）**。

**② 本期 2×2 判定**

四个格子就是 2.1 那张表。条目可能带：链到卡片的链接、`阶段错` 徽章、`黑名单` 徽章、一句话 note。标题右侧是本期 headline。

**③ 扫描历史**：每期的日期 + 一句话结论，点进去看全貌。

**④ 纯炒作黑名单**：主题 + 判定日期 + 结论摘要。完整理由（表面现象、判定理由、重新评估条件）在 `surf/blacklist.yaml`；当期扫描页的 summary 里一般有对应的判定段（如 #001 的「判定为纯炒作：A 股军工」）。**入黑名单不等于永久排除**——出现真实产业变化就重新评估。

### 3.3 卡片页 `/surf/card/{slug}` —— 单张卡片的全部

从上到下的顺序是**刻意**的：先给每周要核对的东西，再给背景材料。

**① 交易参数**

`建卡参考` / `硬止损` / `技术止损(ma60)` / `目标` / `距止损` / `距目标` / `盈亏比` / `持有` / `仓位`。

页头标明**现价取自哪里**：`latest_quotes.csv`（最新收盘）→ 当期扫描快照 → 建卡参考价，三级回落，并标注日期。**永远是收盘价，不是盘中价。**

> **可能有漂移警告框。** 当最新收盘与建卡参考价偏离 ≥1% 时出现（扫描 #001 两张卡片都踩过：建卡时新浪当日数据未发布，参数冻结在前一天，实际标的已涨 +3.96%、距 ma60 达 12.0%）。
> 按最新收盘算出的风险若**超出 8-10% 的设计区间**，框会变红并提示：**此时追入等于自行放大单笔风险，应等回踩或缩减首笔仓位。**
> **建卡参数不回改**——那是向前验证的记录。看到红框就用最新收盘自己重算入场距离。

**② 证伪条件**（提到正文之前，这就是每周要核对的清单）

按层级分组（价格层 / 资金层 / 产业层 / 逻辑层 / 相对强度层 / 结构层），每条显示：

- `●` = 已触发，`○` = 未触发
- 证伪条件的文字
- **`建卡时：…`** —— 建卡时的对照值（baseline），没有它就无法判断「现在算不算触发」
- 可选 note：这条为什么致命 / 触发意味着什么

页头 `x/y 触发 · 状态由每周扫描写入，本页只读`。**触发 → 离场，不留情面。**

**③ 个股增强层**（只对左上角卡片有）

- **进交易清单**（`verdict: follow`）：标的 + 链上卡位、`超额20` / `超额60`（相对基准 ETF）、位置分位、量能比、最新收盘（悬停看日期）、止损价、距止损、仓位
- **观察池 / 已否定**（`watch` / `reject` / 港股 `不可交易`）：只给指标，不给止损与仓位。观察池是系统唯一的自我校准来源——下轮回看它究竟是「太早」还是「市场已看穿它不兑现」
- **`行情` / `财务` 链接**：只有 prism 已覆盖的公司才可点。显示「prism 未覆盖」表示点进去会 404——**链接的有无本身就指示「这只有没有做过基本面功课」**
- 底部 `需要基本面深研（surf 不做）` 列出 `prism_refs`，建议单独开 prism 主题

判定判据速记：**20 日超额 ≤ 0 = 市场不认它是这轮的兑现方，不进交易清单；空头排列一票否决**。ETF 触发证伪 → 该卡片下所有个股**无条件同步离场**。

**④ 指标时间序列**：从历次扫描快照中按代码抽取，用于向前验证。只有一期扫描时会提示「下次扫描后此处出现对比」；标的不在候选池（如美股个股）时说明无时间序列。

**⑤ 卡片正文**：七段固定结构，右侧带 sticky 目录。标题旁有「单页」（`card.md` 的独立渲染页）与「原文」（纯文本），决策日志同理。

```
① 趋势成因与背景   驱动力类型 + 可核实的证据链（必须含反面证据）
② 阶段判断         0→1 导入期 / 1→10 放量期 / 10→100 成熟期
③ 技术佐证         RS、位置分位、趋势结构、量能、资金流、广度
④ 上涨空间         测算方法（渗透率 × 市场规模，或回到前高）
⑤ 交易对象         ETF 打底 + 龙头个股 ≤3 只；选谁、不选谁的理由
⑥ 交易计划         入场条件、目标位、盈亏比、双层止损与仓位
⑦ 证伪条件         什么情况下承认判断错误（与 ② 的清单逐条对应）
```

**⑥ 决策日志**：只追加。建卡时记了什么、**当时我可能错在哪**、下次该检查什么，都在这里。这是事后判断「当初是不是在自欺」的唯一材料。

> **状态的数据源是 `card.md` 的 frontmatter，不是正文里的文字。** 正文手写「状态：可跟随」不作数。

### 3.4 扫描页 `/surf/scan/{date}` —— 某期的全貌

标签页切换：

- **技术佐证与 2×2 判定**（`summary.md`）：当期数据质量问题、市场整体状态、每个候选趋势的判定理由、通道 B 的发现、2×2 填表、**本次扫描修正了产业扫描的哪些结论**（留痕，不粉饰）
- **通道 A 产业扫描原文**：带时间戳的产业判断原始记录，**写在看行情之前**。事后如有改口，对比这里和判定结果就能看出来
- **五张指标表**：A股 ETF / 美股 ETF / 行业资金流（同花顺 90 行业·5 日）/ 行业广度（当日涨跌家数）/ 概念资金流（387 概念·5 日）。**点列头可排序**，第二下反向

**每篇都能单页打开或取原文。** 文档标签页顶部有「单页打开」（独立渲染页，一个 URL 只装一篇，可收藏可分享）与「原文」（纯文本，复制/跨期 diff/丢进编辑器用它）；表格说明行的「原文」给 CSV。

**标签页和章节都能直接链接。** 点标签会把地址写成 `#d-2` 这样的 hash，点右侧目录会写成 `#d2-…`——两者都能新标签页打开、收藏、贴给别人，刷新后也停在原处。（跳转前会先切到目标所在的标签页：hash 指向的正文如果在另一个标签里，浏览器自己不会跳。）

### 3.5 候选池 `/surf/universe` —— 覆盖面与盲区

**这页存在的主要理由是「没进过 2×2」那一栏。** A 股 / 美股分开，每块六段，按信息价值排序（不是漏斗顺序）：

| 段           | 含义                                              | 默认     |
| ----------- | ----------------------------------------------- | ------ |
| **建卡**      | 该主题就是卡片标的所在主题                                   | 展开     |
| **判定淘汰**    | 进过 2×2 但不在左上角，或同向未选作载体。带判定 + 理由 + **下期动作**      | 展开     |
| **真 · 未讨论** | 没进过 2×2，且至少有一条技术判据在喊                            | **展开** |
| 技术层零支持      | 没进过 2×2，四条判据一条都不中                               | 折叠     |
| 结构性不覆盖      | 框架对它不适用，**不计入覆盖率分母**                            | 折叠     |
| 入池前剔除       | 机械原因（资产类别 / 非趋势载体 / 流动性不足 / 同主题折叠 / 抓取失败），按原因分组 | 折叠     |

**「判定淘汰」与「真 · 未讨论」的区别是本质的**：淘汰是**我看过并否了**（下期按原因分级复看），未讨论是**我压根没看**。

- 「未判定」原先混着三类性质完全不同的东西，现在拆开了。扫描 #002 的 57 个未判定里，**只有 14 个属于真盲区**（A 股 4 / 美股 10）。
- **结构性不覆盖**登记在 `surf/theme_scope.yaml`：金融（驱动力是利率与资产质量，不是产业供需）、行业容器（XLK/XLI 等 GICS 行业级 ETF，成分按行业分类聚合而非产业趋势）。加一条进来门槛很高——理由必须是**框架性的**，不能是「这期技术不好」（那是判定）。
- **技术层零支持是分诊不是判定**：四条「值得看一眼」的信号是 `多头排列` / `RS5≥60` / `放量` / `中期强且在高位`（RS60≥60 **且** 位置分位≥60）。一条都不中 ≠ 判定过，只是无声跳过是合理的。页面上直接显示命中的是哪几条。
- 「放量」门槛取**池内 75 分位**（下限压在 1.0），不用固定值——实测 A 股池量能比中位 0.64、美股 0.96，固定 1.0 等于对两个市场用两把尺子。

页头给出漏斗数字：**抓取 N → 入池 M 只 / K 个主题 → 框架内 X → 已判定 Y（Z%） → 建卡 W**，并说明覆盖率分母已剔掉结构性不覆盖的那批。

> **本期通道 A 还没跑时**（判定层回落到上一期），页头会出现提示条：主题划分按新口径重建，所以上期没讨论过的主题会全部落在「真·未讨论」或「技术层零支持」——**这不是数据缺失，是上期确实没看过它们**。

每期候选池留痕都保留，底部「其他扫描期」可切换。

### 3.6 读表速查

页面和 CSV 里的列，含义与读法（DESIGN §6.2）：

| 列 | 含义 | 怎么读 |
|---|---|---|
| `ret5` / `ret20` / `ret60` | 5 / 20 / 60 日涨幅 | **三个尺度都要看**。只有 ret5 强 = 超跌反弹；只有 ret60 强 = 可能滞涨。ret20 会把刚启动的反弹与前一段下跌互相抵消，**不可替代 ret5** |
| `RS5` / `RS20` / `RS60` | 上述涨幅在候选池中的百分位 | 池内相对排名（**折叠同主题之后才算**，否则会被同主题十几只撑坏） |
| `位置分位` | 现价在近 250 日高低区间中的分位（0-100） | 山脚还是山顶，**防追高**。极低（<10）说明资金根本没进来 |
| `距250日高` | 距近 250 日最高点的回撤 | 识别「二波」形态的前提 |
| `趋势结构` | 多头排列 / 空头排列 / 均线纠缠偏多 / 偏空 | 空头排列下的上涨是反弹不是趋势。**但空头排列不排除该标的**——二波的前置状态就是它 |
| `量能比` | 近 5 日 / 前 60 日日均成交额 | **< 1（未放量）时必须说明为何仍判技术确认，并降低该卡片优先级** |
| `板块5日资金净额_亿` | 映射板块近 5 日资金净流入（仅 A 股） | 涨但资金净流出 = 散户游资推动，主力在出货 |
| `板块当日广度_%` | 映射板块上涨家数占比（仅 A 股） | **不能单独用**：当日快照，低广度 + 高涨幅 = 少数权重股伪装成板块行情；高广度也可能是普涨式派发。必须与 ret5/ret60、资金流同看 |
| `折算修正` | 该标的被识别出的份额折算次数 | 非 0 说明历史经过份额折算复权，**数值可信但需留意** |
| `超额20` / `超额60` | 个股涨幅 − 基准 ETF 同期涨幅 | 个股层用超额，**不用 RS 百分位**（候选只有 5-8 只，池内排名无统计意义） |
| `ATR20` | 近 20 日平均真实波幅 / 现价 | 定个股止损幅度用（§8.1） |

**别忘了检查阶段**：产业逻辑成立 + 技术确认，但 `ret250` 已经 +500%，那是成熟期，不是机会。

### 3.7 数据新鲜度与写入规则

| 产物 | 何时更新 | 注意 |
|---|---|---|
| `scans/{date}/*` | 扫描时写入 | **向前验证的历史记录，不可回改。** 发现错误也不改，在下一期说明 |
| `surf/latest_quotes.csv` | `refresh_quotes.py` 刷新（Step 0） | 卡片标的的最新收盘价，**绝不回写 `scans/`**。距止损必须用它算 |
| `cards/{slug}/card.md` | 扫描时更新 frontmatter 与正文 | 状态与证伪触发以 **frontmatter** 为准 |
| `cards/{slug}/log.md` | 每次扫描追加 | **只追加，不修改历史** |
| `matrix.yaml` | 每期扫描时写入 | 首页矩阵读它，**漏写则矩阵为空**。判定必须与 `summary.md` 一致 |

页面是**实时读文件**的：改了 `surf/` 下的数据文件**刷新即可，无需重启服务**；只有改了 `app/routes/surf.py` 或 `app/templates/surf/` 才需要重启（`launchctl kickstart -k`）。

## 4. 怎么用（对话触发）

直接对 Claude 说：

| 你说 | 会发生什么 |
|---|---|
| **「surf 扫描」** / 「本周扫描」/「趋势扫描」 | 完整跑 Step 0 → 4。这是每周一次的主入口（个股增强层是 Step 5，由下面的「补个股」单独触发） |
| **「复查卡片」** / 「卡片还成立吗」 | 只跑 Step 0：逐条核对证伪条件，触发即离场 |
| **「surf 卡片 {slug}」** | 读某张卡片的正文与决策日志 |
| **「候选池」** / 「扫了哪些」/「盲区在哪」 | 打开候选池页，重点看「真·未讨论」那段 |
| **「加扫 {方向}」** | 重大事件驱动的临时扫描，跳过 Step 0 直接跑 Step 1 → 4 |
| **「补个股」** / 「这张卡片买什么股」 | 只跑 Step 5（需卡片已在左上角） |

**典型节奏**：每周一次完整扫描 + 出现重大产业事件时加扫。中间不需要每天看——周频系统，盯盘没有意义。

## 5. 不看页面，直接读文件

全部是文本文件（Markdown / CSV / YAML），Obsidian 或编辑器直接打开即可；也可以直接在浏览器里取原文：

```
http://127.0.0.1:8000/surf/file/scans/2026-09-22/summary.md
http://127.0.0.1:8000/surf/file/cards/cn-hk-pharma-delivery/card.md
http://127.0.0.1:8000/surf/file/blacklist.yaml
```

**`.md` 打开就是渲染好的单页**（带目录、返回面包屑，一个 URL 只装一篇，可收藏可分享）；要纯文本在 URL 后加 `?raw=1`。三种写法等价：

| 写法 | 例 |
|---|---|
| `surf/` 相对路径 | `/surf/file/scans/2026-09-22/summary.md` |
| 短写 | `/scans/2026-09-21/summary.md` |
| 不带日期（取最近一期有它的那期） | `/surf/scan/summary.md` |

CSV / YAML 一律纯文本——要看这些数据，扫描页的表格视图（可排序）比原文好用。页面上凡是标了「原文」的地方（扫描页每个标签页与表格说明行、卡片页正文与日志）都是这些链接。

> `/surf/scan/{日期}`（如 `/surf/scan/2026-09-22`）是「一期一页」的渲染视图——两篇 tab 切换 + 五张可排序表；上面三种写法是「一篇一页」。两者都能看，取原文加 `?raw=1`。

```
surf/
├── DESIGN.md                 方法论权威版
├── USER-GUIDE.md             本文件
├── scans/YYYY-MM-DD/         每期扫描的全部产出（不可回改）
│   ├── channel_A_industry_scan.md  通道 A 产业扫描（先于行情落笔）
│   ├── summary.md                  技术佐证与 2×2 判定
│   ├── matrix.yaml                 2×2 的机器可读版（首页读它）
│   ├── cn_etf.csv / us_etf.csv     ETF 指标快照
│   ├── cn_boards.csv / cn_board_summary.csv / cn_concepts.csv  板块三表
│   ├── stock_candidates.md         个股候选与入选理由（先于个股行情落笔）
│   └── stock_{slug}.csv            个股技术指标快照
├── cards/{slug}/
│   ├── card.md               趋势卡片（frontmatter = 状态数据源）
│   └── log.md                决策日志（只追加）
├── latest_quotes.csv         最新收盘价
├── blacklist.yaml            纯炒作黑名单
├── theme_scope.yaml          结构性不覆盖登记
```

## 6. 别误读的地方

1. **没有胜率。** 这不是遗漏，是设计选择（不做回测）。唯一证据是决策日志的向前验证。
2. **页面价格一律是收盘价，不是实时价。** 首页的现价与进度条取最新收盘（`latest_quotes.csv`），而同页的指标行是当期扫描快照——**两个日期可以不同**，页头各自标注；卡片页有漂移警告框时，说明按建卡参数入场的风险已经变了。
3. **`距止损` 必须看标的是哪一道。** 操作止损 = 硬止损与技术止损里**先触发**的那道（价位更高）。只写「距止损」会被读成硬止损，两张卡片方向可能相反。
4. **指标不是买卖信号。** 它们只描述当下状态，出手与否由 2×2 判定。
5. **`量能比 < 1`、`广度` 单独看都会骗人。** 前者要解释，后者必须与 ret5/ret60、资金流同看。
6. **RS60 不能单独用。** 它是池内百分位，下跌市里「跌得比别人少」的防御板块同样排前面。
7. **同花顺板块指数历史有前视偏差，绝不可用于任何历史验证**（DESIGN 附录 A）。
8. **港股不可交易。** 港股标的照列并标 `tradable: false`（省略会让链条不完整，看不出真正的卡位在哪）；凡该环节只有港股标的，卡片必须补 A 股替代并写明替代代价（纯度更低 / 弹性更小 / 卡位更弱）。
9. **个股永远是增强层。** 单卡片总仓位 ≤ 总仓 1/3，卡片内个股合计 ≤ 该卡片仓位的 40% 且不得超过 ETF 打底。放宽止损由仓位买单，不靠临场自律。
10. **A 股一字跌停时止损无法执行。** 靠流动性门槛部分缓解，不能消除——这是已知代价。
11. **「未判定」不等于「判定为不跟」。** 前者是没进入判断，后者是看过并否了。真盲区只看候选池页的「真·未讨论」那一段。
